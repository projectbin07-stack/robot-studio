# Command line

`bin/robot-studio.js` runs the same code as the page (the DOM-free
`src/core`) under Node 22 or newer, for scripts and CI. Nothing is uploaded
and no network connection is made; `studio` serves the page on 127.0.0.1.
Every output below was produced by the commands shown, on the development
machine (Windows 11, Node 25); simulation output is labelled as such by the
tool itself.

```bash
git clone https://github.com/projectbin07-stack/robot-studio.git
cd robot-studio
node bin/robot-studio.js --help
# or without cloning:
npx github:projectbin07-stack/robot-studio --help
```

## All commands

```text
robot-studio 1.0.0: open any robot model (URDF or xacro)

Usage:
  robot-studio xacro <in.xacro> [--arg name=value ...] [name:=value ...] [-o out.urdf]
  robot-studio check <robot.urdf|robot.xacro> [--arg name=value ...] [--json] [--strict]
  robot-studio new <template> [--set name=value ...] [--format F] [-o out]
  robot-studio export <robot.urdf|robot.xacro> [--arg name=value ...] [--format F] [-o out]
  robot-studio templates
  robot-studio sim <robot.urdf|robot.xacro|template> [--world W] [--route R]
                   [--seconds S] [--seed N] [--out DIR] [--bag DIR] [--imu-cal FILE] [--set k=v]
  robot-studio bag <recording-dir> -o <bag-dir>
  robot-studio replay <recording-dir> [--json]
  robot-studio compare <recording-dir> <robot.urdf|robot.xacro|template> [--json]
  robot-studio studio [--ros ws://robot:9090] [--port 8000] [--no-open]
  robot-studio --help | --version

xacro     expand a xacro file the way the official xacro does and print the
          URDF (or write it with -o). Arguments are given as --arg name=value
          or, as with xacro, name:=value.
check     expand (if needed) and run urdf-inspector's checks plus the mesh
          references; findings are sorted by severity with file:line

new       generate a robot from a template (mecanum, diff, arm); parameters
          with --set name=value (numbers, true/false, x,y,z for positions)
export    open a model (expanding xacro) and export it as the builder does
templates list the templates and their parameters with defaults
sim       drive the robot in a simulated world (wheels, encoders, IMU, LiDAR,
          wheel odometry, scan matching, MCL) and write the recording;
          'robot-studio sim --help' for the options. Simulation output only.
bag       write a recording as a ROS 2 bag (MCAP + metadata.yaml)
replay    replay a recording (simulated, or a bag imported with the Python
          companion robot-studio-bag) through the estimators
compare   run a recording's command schedule on the simulator and compare
          the firmware telemetry (ODOMETRY, WHEEL_STATE) of both runs
studio    serve the page from this computer (127.0.0.1) and open the browser,
          for connecting to a robot on the local network ('studio --help')

  --format F           (new, export) urdf (default), xacro, toml (four-wheel
                       mecanum bases: mecanum-kinematics config) or package
                       (ROS 2 description package as a .zip; needs -o)

Options for xacro, check and export:
  --package name=dir   folder of a ROS package for $(find name) and
                       package://name/ (repeatable). Packages next to the
                       input file's package are found automatically from
                       their package.xml.
  --json               (check) machine-readable report
  --strict             (check) exit 1 when there are warnings and no errors

Exit codes: 0 no errors (and no warnings with --strict), 1 warnings with
--strict, 2 xacro failed or the model has errors, 3 usage or file error.
Nothing is uploaded anywhere and no network connection is made (studio
serves the page on 127.0.0.1 only; the page connects only when you click).
```

`new` writes a template robot and `export` an opened model, as URDF (the
default), xacro, a mecanum-kinematics TOML (four-wheel mecanum bases) or a
ROS 2 description package (`-f package -o name.zip`; CI builds such
packages with colcon in `ros:humble-ros-base`). Details in
[builder.md](builder.md).

```console
$ node bin/robot-studio.js new diff --set camera=true -o bot.urdf
wrote bot.urdf
```

## Simulation: `sim`

Drives a template or any URDF/xacro through a world and writes the
recording; byte-identical for the same seed (CI runs it twice and compares).
The IMU error model can be imu-calibration-lab's combined JSON, which its
CLI writes since 0.2.0 (`imu-calibration-lab combine accel.json gyro.json
mag.json --out imu.json`). Options: `robot-studio sim --help`; settings:
[simulation.md](simulation.md).

## ROS 2: `bag`, `replay`, `compare`

bag (MCAP); the Python companion `robot-studio-bag` turns a bag recorded on
a robot into a recording; `replay` runs a recording through the
estimators; `compare` runs its `/cmd_vel` schedule on the simulator. Below,
all on the simulated run above, so the comparison only shows how closely
the simulator reproduces itself from the recorded commands:

## Connecting to a robot: `studio`

The page on GitHub Pages is served over https; a browser may refuse to let
it open `ws://` to a robot (details and the browsers that were tried:
[ros2.md](ros2.md#reaching-a-robot-from-the-live-site)). `studio` serves
the same page from your computer and opens it, with the robot's address
filled in:

```console
$ npx github:projectbin07-stack/robot-studio studio --no-open --ros 192.168.29.26
npm warn gitignore-fallback No .npmignore file found, using .gitignore for file exclusion. Consider creating a .npmignore file to explicitly control published files.
Robot Studio is served at http://127.0.0.1:8000/?ros=ws%3A%2F%2F192.168.29.26%3A9090%2F
Only this computer can reach it (127.0.0.1). Connect to the robot from the ROS 2 panel; Ctrl+C stops the server.
```

(Run on the development machine with npm 11 on 2026-11-25; the first line
is npm's. Without `--no-open` the default browser opens the address. A page
opened this way reached the fake rosbridge server on `ws://192.168.29.26`
from Chrome 157 and Edge 158 with no permission prompt.)

```text
robot-studio studio: serve Robot Studio from this computer and open it

Usage:
  robot-studio studio [--ros ws://robot:9090] [--port 8000] [--no-open]

  --ros URL     fill in the rosbridge address (the page still connects only
                when you click Connect)
  --port N      first port to try (default 8000; the next 20 are tried if taken)
  --no-open     print the address instead of opening the browser

The server listens on 127.0.0.1 only and serves the page's own files. Stop it
with Ctrl+C.
```

## Exit codes

0 no errors (and no warnings with `--strict`), 1 warnings with `--strict`,
2 xacro failed or the model has errors, 3 usage or file error.
